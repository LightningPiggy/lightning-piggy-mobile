= Expo SDK 58 native dependency audit

Audited on 2026-11-10 for PR #1848, React Native 0.88.1.
This is a source audit, not proof of native compilation or an on-device upgrade.

== Dependency changes

* `@maplibre/maplibre-react-native`: 11.2.1 -> 11.5.1 (newest published 11.x).
  https://github.com/maplibre/maplibre-react-native/blob/main/CHANGELOG.md[11.3.4 changelog]
  documents the Android `getReactTag` fix for RN >= 0.87.
  In 11.5.1, `android/src/main/java/org/maplibre/reactnative/components/mapview/MLRNMapViewManager.kt:265`
  calls `getReactTag()` explicitly. The RN peer is >= 0.80.0.
  The android/ios scan finds only that call and the supported `RCTBridgeModule.h` import.
* `@op-engineering/op-sqlite`: 16.1.1 -> 19.0.5 (newest published stable).
  `ios/OPSQLite.mm:15` declares `OPSQLiteRuntimeProvider`; lines 59-85 obtain the runtime
  through that protocol instead of casting to the removed `RCTCxxBridge`.
  RN 0.88.1's `React/Base/RCTBridgeProxy.mm:99` implements this accessor.
* A reproducible patch for op-sqlite 19.0.5 changes Android's
  `context.catalystInstance.jsCallInvokerHolder` to `context.jsCallInvokerHolder`.
  The latest package still uses CatalystInstance. RN's
  `ReactAndroid/src/main/java/com/facebook/react/runtime/BridgelessReactContext.kt:82`
  can throw on that accessor when legacy architecture minification is enabled;
  its direct `getJSCallInvokerHolder()` at line 186 is supported.
  This patch changes no database path, key, or flags.
* MapLibre's transitive dependencies change: style-spec 24.8.5 -> 26.4.4,
  jsonlint-lines-primitives 2.0.2 -> 2.0.3, unitbezier 0.0.1 -> 1.0.0,
  and Turf distance/helpers/invariant/length/meta/nearest-point-on-line 7.3.5 -> 7.4.0.

source (GitHub's release list stopped at 19.0.4 when queried).

No app API rewrite is required for the methods actually used. The updated regression
tests check the existing-name/key open and SQLCipher format setup before the schema
fast path. Node SQLite-backed tests exercise schema/transaction behavior, not encryption.

== Existing encrypted database compatibility

`package.json` continues to enable only `"op-sqlite": { "sqlcipher": true }`.
There are no custom `sqliteFlags`, cipher settings, app-group override, or location override.
`src/services/localDb.ts` opens `lightningpiggy.db` using the existing SecureStore key.
The key is neither rotated nor converted to a hex-literal/raw-key representation.

The evidence supports in-place readability: no file-format, filename, default-location,
key-encoding or default-open-flag change was found. The app now explicitly executes
`PRAGMA cipher_compatibility = 4` after keying and cipher availability verification,
before `PRAGMA user_version` (the first actual page read), including already-migrated
files. This pins the existing settings; it does not migrate, rekey, or rewrite the DB.
The native open performs no page-reading query before returning to JS.

The existing wrong-key self-heal deletes an unreadable database and its key. That behavior
predates this upgrade; preserving cipher settings before the first page read is therefore
particularly important. No encrypted production file, native compile, or device was used
in this audit. A real 16.1.1 -> 19.0.5 encrypted-file reopen remains unverified.

== Complete native scan inventory

Enumerated installed packages, including nested packages and examples, with android/ or ios/
directories. Excluded React Native core and expo-* packages from dependency matching;
also inspected Apple and C++ source outside those directories and all modules/ sources.

getCatalystInstance / Kotlin catalystInstance, CatalystInstance, UIManagerModule,
LegacyArchitecture, and bridge-based JSI/call-invoker access.

A name match alone does not mean RN removed the API. The installed RN 0.88.1 still
ships RCTBridgeModule, CatalystInstance, NativeModule.onCatalystInstanceDestroy,
UIManagerModule.CustomEventNamesResolver and setViewLocalData (the latter is a no-op).
